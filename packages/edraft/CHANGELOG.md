# Changelog

All notable changes to the eDraft Screenwriting Engine will be documented here. The project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- FDX import reads Final Draft's ScriptNotes: `FdxImportResult.scriptNotes` (and `FdxDocument.scriptNotes`) lists each note in file order with its author (`WriterName`), title, category (`Type`, free text), colour and dates verbatim, its `Range`, the `anchor` that Range lands on in `script.elements`, and its body text. Ranges count every script paragraph with one unit per paragraph break — the absorbed End of Act included; a Range that starts past the script keeps its `range` and has no `anchor`. Notes are a reading of the file, never written: the preserving save still copies `<ScriptNotes>` byte for byte. `WriterID` is not read. Bounded by `maxParagraphs`/`maxTextRuns` (`FDX_SCRIPT_NOTES_LIMIT_REACHED`).
- Action lines now grow into transitions the way they already grew into scene headings: typing a transition's opening in an action block (`CUT`, `SMA`, `FADE`…) offers the real transitions as promotions (`becomes: 'transition'`), house transitions before the defaults — accepting converts the block in place. Scene prefixes and transition openings never share letters, so one typed line can only mean one of them.
- Character renaming as a document-wide refactor behind `@edraft/core/analysis`: `renameCharacter` rewrites every cue by base name — case-insensitively, extensions (`(O.S.)`, `(CONT'D)`) and dual-dialogue flags preserved, prose never touched — pure, copy-on-first-write, and a true no-op (same array reference) when nothing matches. `nameDriftGroups` unions near-miss cue names (MARA / MARIA / MARIE) into one-click merge candidates; merging is always the writer's call, never automatic. `normalizeCueName` is the shared canonical cue form, and the extension pattern is exported as `CUE_EXTENSION_RE` so stripping (SmartType) and preserving (rename) share one source of truth.
- Universal import behind `@edraft/core/import`: a shared classifier that gives every imported line a type, a confidence, and a plain-language reason, with low-confidence lines flagged in an `ImportReport` for writer review.
- Dependency-free `.docx` import: hand-rolled ZIP reader (stored + deflated via the platform's native `DecompressionStream`, CRC-32 integrity, size caps) and OOXML reading for styles, indents, alignment, page breaks, tracked changes, tables, and images.
- Plain-text and paste import covering typewriter layout and reflowed prose, with pagination artifacts (`(MORE)`, `CONTINUED`, page numbers) stripped and counted.
- `.docx` export (`writeDocx`) closing the round trip: production-office OOXML with Courier New 12pt, screenplay margins and indents, `keepNext` speech protection, and title-page emission — verified by reading exports back through the importer.
- PDF round trip: exported PDFs carry the complete Fountain source as a versioned, UTF-8-safe payload in the Info dictionary (`pdfsignal`), alongside `/Producer` and `/Title` metadata. An eDraft PDF re-imports perfectly; a foreign PDF is refused with a clear message — no PDF-parsing dependency, ever.

### Fixed

- A note inside a dialogue block no longer turns the cue and the speech into Action. The editor puts a note in front of the line it is about; on a speech or parenthetical line, the serialiser wrote it as its own paragraph between blank lines, which ended the block, and the next open read the cue and the speech as Action. An FDX save then wrote them into the file as Action paragraphs. A one-line note inside a block is now written inline at the end of the line after it (`Hello. [[note]]`), where the reader lifts it out and puts it back exactly where it was. A note of several lines, a section or a synopsis, which Fountain cannot carry inside a block, is written in front of the block's cue: the block survives and nothing is lost, but that aside moves to the cue's line. Scripts with no aside inside a dialogue block are written exactly as before.
- A note whose text ends in `]`, or holds `]]`, survives save and reopen. The serialiser wrote `[[` + text + `]]`, so `see [scene 4]` went to disk as `]]]`; the parser closed at the first `]]`, and the next open cut the note short and printed a stray `]` action line into the script. An .fdx took the same path through Fountain, and any save, even one with no edit, wrote that `]` into the file as an Action paragraph. The parser now reads a run of `]` as text plus close, so the `]]]` already on disk reads exactly. The serialiser writes a space between adjacent `]` inside a note and one before the close when the text ends in `]`, so a written note's only `]]` is its close. A note with neither is written as before. Lossy by choice, one way: a note whose own text holds `] ]` comes back as `]]`.
- A save keeps Final Draft's ScriptNotes on their words. `<ScriptNotes>` was copied byte for byte, so after any edit every Range counted positions in a script that was no longer there — measured on a file Final Draft wrote, one word typed near the start moved ten of eleven notes off their words. The preserving save now rewrites the Range value of each note whose words moved, counted as Final Draft counts: each end stays with its character, so text typed inside a note joins it and text typed at its edges does not; a note whose words are all deleted closes to zero length where they stood (`FDX_REWRITE_SCRIPT_NOTE_WORDS_DELETED`); a Range already past the script's end keeps its bytes, a reversed pair stays reversed, and nothing else in `<ScriptNotes>` changes. Moved Ranges are reported as `FDX_REWRITE_SCRIPT_NOTE_RANGES_MOVED` under a new `info` severity, which `warnings` leaves out.
- Dual dialogue from Final Draft is no longer invisible. Final Draft keeps it as a paragraph with no text of its own holding a `<DualDialogue>`; the import read those paragraphs as metadata, so each block arrived as one empty General element — in two files Final Draft wrote, all 48 lines of 12 dual dialogues were missing. Each line now imports as the element it is, the second speaker's cue `dual`; any other paragraph holding a `<DualDialogue>` (text of its own, or two blocks) imports as before and is reported (`FDX_DUAL_DIALOGUE_NOT_READ`). The preserving save treats each line as its own paragraph — kept as its bytes, or with the writer's edit merged — inside Final Draft's block, written verbatim around them; lines added within the pair are written inside the block; a pair the writer no longer keeps dual (the second cue un-dualled, or its lines apart) is written in its place as ordinary paragraphs, each keeping its bytes, and reported (`FDX_REWRITE_DUAL_DIALOGUE_DISSOLVED`). A save with no edit still returns both files byte for byte. ScriptNote anchors move to the new element indices; a new dual pair made in eDraft is still written as `Dual="Yes"`, not a Final Draft block.
- ScriptNotes land where Final Draft's Range points after a dual dialogue or an omitted scene. A Range counts each block Final Draft embeds in a script paragraph (`<DualDialogue>`, `<OmittedScene>`) as two units, its own paragraphs' text as nothing; the reader counted them as zero, so every note after one landed two units late per block. Measured on two files Final Draft wrote: two notes in each began mid-word and one in each fell past the script's end with no anchor. Now every note in both lands on whole words or is empty — the notes past five dual dialogues cover exactly the action line and the line of dialogue they were written on. Only `anchor` moves: the imported screenplay, `range`, and every byte a save writes are unchanged.
- Editing a paragraph of a Final Draft file no longer rewrites it from the edited element. Measured through the app's path on files Final Draft wrote: a one-letter typo fix collapsed a line's 11 runs into one and lost 5 tags and a revision mark; an edit to the emphasised numbered heading Fountain reads as Action made it `Type="Action"`, dropped its SceneProperties and 7 tags, and wrote Fountain's `#2#` into its text; an italic `(beat)` became Dialogue; a two-line Summary was cut at its line break; a trailing space and an AllCaps word's stored letters were lost. With `rewrite(script, { unedited })`, an edited paragraph is now merged: the writer's change (unedited reading → edited element) is placed onto the file's own text by character alignment, casing aside, so what Fountain added is never written and what it dropped stays. Runs the change does not touch keep their bytes; runs it touches keep their attributes, with the writer's bold, italic, underline and strikeout applied; typed text takes its run's tags, font, adornment and AllCaps but never its RevisionID. The file's Type stands unless the writer changed the element's kind, and a split paragraph stays one paragraph when its lines are edited in place. An edit that cannot be placed without guessing — one touching only what Fountain added — is written as before and reported (`FDX_REWRITE_EDIT_UNPLACED`). Proven in both engines on the Final Draft-written fixtures, by a sweep asserting an edit changes bytes only inside the runs it falls in.
- Saving a Final Draft file no longer rewrites paragraphs nobody edited. Measured on a file Final Draft itself wrote, a save that changed nothing rewrote 8 headings through the engine alone — the save compared Final Draft's split runs with the model's merged ones — and, through Fountain, lost 400 of 407 production tags, revision marks and a scene's SceneProperties, because Fountain carries none of them and the save called every such paragraph edited. The run comparison is canonical on both sides now, and `openFdx(xml).rewrite(script, { unedited })` takes the caller's own reading of the file before any edit: a paragraph whose element — or the run of elements its lines became — comes back exactly as it was read is written as its original bytes (`FDX_REWRITE_UNEDITED_UNALIGNED` reports paragraphs the reading could not be paired with). Proven on anonymised copies of two files Final Draft wrote, which fail on the previous save, guarded against fixtures that could not fail.
- Saving a Final Draft file no longer loses or corrupts its End of Act cards. The import absorbs End of Act, so no element stands for one; `openFdx().rewrite` left them to the alignment, which deleted every card on every save — even with no edit — and paired a card without `Alignment` with the writer's next edited paragraph, writing their words as an act card and dropping the real paragraph. Absorbed paragraphs now stay out of the alignment and are written back verbatim before the next paragraph the save keeps, or after the last element when none survives; never dropped. A save with no edit returns the file byte for byte.
- Paste classification of blank-line-free text (chat apps, AI exports, prose): an uppercase cue-shaped line now interrupts an attached speech run as a new speaker instead of folding into the previous dialogue, colon-bearing uppercase lines are read as labels rather than cues, and uppercase camera framing (`CLOSE ON`, `INSERT`, `POV`, `SHOT -`…) classifies as `shot` with the prose beneath it read as what the camera sees. Shouted dialogue keeps its terminal punctuation, so shouts stay speech.
- Fountain import no longer eats a foreign script's opener: a lone leading `Key:` line is a title page only for known keys (`Title:`, `Credit:`…) or a run of two or more keys, so `FADE IN:` stays in the body where it belongs — and the FADE opener/closer family is now detected as transitions on import and serialised bare.
- `.docx` round trip preserves multi-line elements: line breaks inside an element travel as in-paragraph `<w:br/>` runs and fold back into one element on import, instead of returning as sibling elements with the continuation flagged low-confidence. Multi-line title pages drop once instead of between every line.
- Text import normalises mid-line tabs (Word tab stops, typewriter layout) to spaces instead of leaking raw tab characters into element text.
- `(CONT'D)` is suggested again whenever the same voice continues in a scene — resuming after action *or* simply speaking again, matching Final Draft. The port had tied it to an intervening action beat, so `MARA` → dialogue → `MARA` + space whispered nothing. The empty-block guess still requires the action beat; the explicit gestures (typing `(` or the name plus a space) now need only the fact of continuation.

## [0.1.0] - 2026-08-10

### Added

- Typed screenplay document model and runtime validation.
- Fountain parsing and serialization.
- Best-effort FDX import and deterministic export with diagnostics.
- Deterministic screenplay pagination and runtime estimation.
