## Specific technical question about this app

eDraft's engine paginates by **counting characters** — 60 per line, 55 lines per
page — and that pagination is authoritative (the PDF is generated from it, and
studios schedule against the page count).

If `**bold**` markers live inside the element's text, the paginator would count
the markers toward the 60-character line width and wrap early, producing wrong
page counts. The other assistant claims this is fixable with a "printed length"
function that ignores markers, used by the wrap.

**Is that the right fix, or does it indicate the markers shouldn't be in the
model text at all?** Consider that Fountain's spec says emphasis markers are not
printed.
